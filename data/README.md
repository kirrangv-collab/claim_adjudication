# Research data policy

This project does not contain the original frozen 24-case adjudication benchmark. It was not in the supplied workspace and must not be reconstructed from the mentor report's summary metrics.

## Public real-world data source identified

- **Dataset:** CMS Medicare Physician & Other Practitioners by Provider and Service (2024 resource; catalog last updated 2026-05-21).
- **Publisher:** Centers for Medicare & Medicaid Services (CMS), U.S. Department of Health and Human Services.
- **Official catalog:** <https://catalog.data.gov/dataset/medicare-physician-other-practitioners-by-provider-and-service>
- **Official CMS dataset page:** <https://data.cms.gov/provider-summary-by-type-of-service/medicare-physician-other-practitioners/medicare-physician-other-practitioners-by-provider-and-service>
- **2024 catalog resource API URL:** <https://data.cms.gov/data-api/v1/dataset/92396110-2aed-4d63-a6a2-5d6207d46a29/data>
- **Data type:** annual provider/service aggregate utilization, charges, and payments, organized by provider NPI, HCPCS code, and place of service; it is not case-level insurance adjudication data and has no approve/deny ground-truth labels.
- **Use here:** contextual analysis or prototype UI demonstration only. It cannot validly train/evaluate coverage adjudication or support claims about adjudication accuracy.
- **Conditions:** review and comply with the source's current CMS Public Use File terms and documentation; cite CMS; do not attempt to re-identify anyone.

## Download status

The catalog identifies the 2024 resource and its official API URL, but no source data is checked into this folder. The official dataset page and API resource returned an Akamai HTTP 403 access-denied response from this environment, so the dataset could not be retrieved or verified here. The exact source and failure are recorded in `manifest.json`. Do not substitute an unofficial mirror or fabricate a dataset. Once the official CMS download/API link is available from an allowed network, save the unmodified source as `data/raw/` and record its exact URL, publication year, retrieval timestamp, file size, SHA-256, accompanying data dictionary, and applicable terms in the manifest before any processing.

Never put patient-level claims, PHI, credentials, or data requiring a restricted CMS data-use agreement in this public demo workspace.

## Real CMS policy corpus and evaluation sample

`processed/ncd_eye_policy_sections.json` holds unmodified excerpts of the CMS National Coverage Determinations Manual (Chapter 1, Part 1, section 80 – Eye) with source URL, retrieval time and SHA-256. `processed/ncd_eye_evaluation_cases.jsonl` pairs that text with synthetic clinical vignettes and project-authored labels; it is generated by `scripts/build_evaluation_cases.py`, which documents every label's rationale.

- **v1 (10 cases)** — used while developing the five-agent pipeline, so pipeline results on them are in-sample.
- **v2 expansion (12 cases)** — labels were written from a literal reading of the cited section *before* the pipeline was run on them, including two noisy multi-encounter notes (family history only; an earlier "no glaucoma" encounter followed by a current diagnosis) that exercise Agent 2's active-encounter isolation. Running them surfaced four general bugs that were then fixed, so treat them as semi-held-out, not as a clean test set.

The sections file also serves as the **reference corpus** that the knowledge layer indexes into the vector store (sentence passages) and the graph store (`PolicySection -[:MENTIONS]-> Concept`).

## Ontology (`ontology/eye_ontology.json`)

A small curated knowledge graph used by Agents 2 and 3:

- **ICD-10-CM concepts** (`system: ICD10CM`) — real codes and titles for the conditions referenced by the NCD 80.x corpus (e.g. H40.11 primary open-angle glaucoma, H35.32 exudative AMD, H52.1 myopia, H27.0 aphakia). ICD-10-CM code titles are U.S. government works published by CMS/CDC (NCHS) and are in the public domain. Titles are occasionally abbreviated and laterality/7th-character extensions are omitted. Chapter and block nodes are marked `va_eligible: false` so they are never used as KAMEL valid ancestors.
- **Project-defined concepts** (`GROUP`, `FINDING`, `PROC`, `DEVICE`, `DRUG`) — research constructs, not an official terminology (e.g. "Predominantly classic CNV", "Radial keratotomy", "Verteporfin"), with hand-curated synonyms. `treats` edges link a procedure/device/drug to the conditions it is indicated for; they are only used to connect a claimed diagnosis to procedure-centric text.

This ontology is not a substitute for a licensed terminology service and only covers the eye-chapter research corpus.

## Confidence calibration (`calibration/pipeline_calibration.json`)

Written by `scripts/calibrate_confidence.py`. It runs the deterministic pipeline on the labelled sample, takes Agent 5's raw logit for each decisive (APPROVE/DENY) draft and fits Platt scaling (shrunk towards identity) to the target "draft equals label". The fit is **skipped** — the identity map is kept and the reason recorded — unless at least three correct and three incorrect decisive drafts exist, because Platt scaling cannot be identified from a single outcome. The current file records 16 decisive drafts with 0 errors, so raw scores are used. It is fitted on the same sample used by the in-app evaluation, which is disclosed in the file and via `/api/v1/config`.

## Scenario test suite (`test_cases/guide_test_cases.jsonl`)

51 hand-authored scenarios used by `testing_guide.md`, `scripts/run_test_cases.py` and `tests/test_guide_cases.py`, generated by `scripts/build_test_cases.py`. Synthetic policies exercise specific logic (EXCEPT, UNLESS, ONLY IF, AND/OR, quantities, out-of-domain text); real-policy scenarios load unmodified NCD 80.x text from `processed/ncd_eye_policy_sections.json`. All clinical evidence is synthetic. Expected outcomes were written before the suite was first run; the first run exposed nine conservative misses that led to general fixes, so the suite is a regression suite, not a held-out benchmark.
